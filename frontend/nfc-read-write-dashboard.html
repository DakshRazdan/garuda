Batch details

Every unit belongs to a batch already registered on the regulator's ledger. This form only prepares the chip — it does not create the batch record.

Use the format BATCH-YYYY-NNN, e.g. BATCH-2026-001.

Unit identity & signature

The unit ID and signature are the only two fields written to the chip. Everything else about the product stays on the regulator's ledger and is looked up when a customer scans the tag.

Demo signing. This tool computes the signature in the browser so the demo works offline. In production, the unit ID and signature must be issued by the regulator's server using a private key that never leaves the backend — otherwise anyone could forge a valid-looking tag.

Chip payload & memory budget

An NTAG213 has 144 bytes of user memory. After the NDEF message overhead, roughly 137 bytes are usable — this is why only the two identity fields go on the chip.

Where this tool fits

The GI Volume Reconciliation Engine authenticates GI (Geographical Indication) tagged produce by pairing each physical unit with an NFC chip that carries only a unit ID and a regulator-issued signature.

This Field Encoding Station is the issuer-side half of that system: an authorized packer writes a chip for each unit as it leaves the packing line. The consumer portal is the other half — a shopper taps the same chip and the portal calls the ledger's /verify endpoint to check the unit ID, signature, and chip UID against the regulator's records.
